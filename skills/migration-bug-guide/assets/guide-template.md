## 2. 新旧实现与关联入口

填写已核实的目标路由、组件、旧版路由与可达组件、接口封装、语言资源，以及必要的转发宿主。跨仓库路径必须注明基准与角色。说明当前映射来源是源码还是运行验证。

## 3. 事实与冲突处理

以旧业务实际行为和可达源码为对照，结合后端契约核对目标实现。Bug 描述、历史文档和注释仅作线索。运行、源码、契约不一致且会改变结果时记录冲突，不猜测。用户已确认的新需求优先作为例外保留。

## 4. 修复流程

明确入口、操作、数据、权限与语言条件；按项目工具规范尝试复现并记录现象、Console 和请求；追踪新旧调用链，说明根因、差异和最小方案，再修改直接相关文件。无法复现时用明确的源码或请求证据支撑判断，否则报告调查结果。保留无关工作树差异。

## 5. 接口与异步语义

核对方法、路径、query/body、字段名、类型、层级、默认值、顺序及最终序列化。区分省略、undefined、null、空字符串、空数组、0、false 和不发请求；不把某次 null 修复推广为全部请求规则。

追踪请求条件、串并行、分页、取消、过期响应、轮询和错误分支。区分统一错误提示与 Promise 的 resolve/reject；验证业务或 HTTP 失败后不会错误提示成功、关闭编辑界面或进入下一步。具体配置读取当前项目规则与封装。

检查同接口受影响调用方；生成接口的改动遵守当前项目规范，不通过改类型掩盖未经证实的契约差异。

## 6. 模块检查重点

## 7. 交互与视觉

业务语义沿用确认的基线，界面外壳遵守目标项目规范。核对可见文案、禁用与加载态、空态、点击传播、关闭确认和刷新时机；局部样式不得扩大影响其他控件。

## 8. 验证与交付
