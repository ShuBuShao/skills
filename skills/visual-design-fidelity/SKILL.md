# 设计稿还原与视觉验收

将每项视觉要求对应到可追溯的设计证据和可复测的浏览器结果。明确要求验收时交付报告。获得实现授权时，先建立基线，再修正并复测。业务行为与设计稿冲突时，说明冲突并确认该项的处理方式。

## 建立基线

- 从用户指定的页面、设计版本、画板、图层及状态确定范围。优先使用 MasterGo 的只读图层与分区数据，按目标画板读取对应状态，取文字样式、填充、描边、尺寸和布局信息。保存可定位的图层 ID 或链接。其他工具提供同等标注时采用同一取证方式。
- 只有截图时仍可对照可观察的颜色、布局、间距与状态。能确认画板尺寸和导出比例时，才把图片像素换算为设计尺寸并注明是估算。图层标注不可得的属性标为未标注，无法从截图观察的项目注明原因。
- 用[验收表模板](assets/visual-audit-template.md)按状态记录元素、属性、期望值、单位和来源。优先采用用户确认的来源。旧版、设计稿和现有实现不一致时，逐项记录取舍。修改已有页面时，设计没有规定且用户没有指定的属性沿用现有表现。
- 选取与任务相关的属性，包括字号、字重、行高、颜色和透明度、圆角、尺寸、相邻元素间距、对齐和显隐。遇到满高背景、滚动容器或长文本换行时，将覆盖范围、滚动结果或换行行为单独列为验收项。

## 实现与复测

1. 按项目规范定位负责渲染的组件和样式。优先修改能解释差异的布局规则或样式来源，控制影响范围。验收表中尚未裁决的冲突保持待确认。
2. 在设计基准视口、固定数据和相同页面状态下取证。记录视口、语言和数据条件，按需要记录主题、字体、设备像素比或容器。短内容、长内容或不同视口会改变结果时，补测受影响的条件。
3. 页面进入目标状态后，从 `getComputedStyle()` 读取字号、行高、颜色等生效属性，必要时检查伪元素。从 `getBoundingClientRect()` 读取尺寸和边缘间距。动画或字体加载影响数值时，等状态稳定再测。渲染截图用来核对整体层次及计算样式无法证明的效果。
4. 逐项填入实测值和差值。比较数值时统一单位，按属性注明容差及依据。文字、颜色和显隐等离散结果明确核对。已标注且实测符合要求才记为通过。截图估算、未标注和未测分别注明，截图并排对照不能证明未读到的精确属性。

## 交付

给出各状态截图、验收表、剩余差异和未测原因。说明使用模拟数据、占位图标或浏览器模拟容器的范围。仅在本轮实际测到的环境和状态上给出结论。视觉调整影响既有交互时，按相关状态回归并记录结果。
